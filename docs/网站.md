# 网站

[Amazon 营销与 AI](https://amazon-marketing-digest.jasmineztoh.chatgpt.site) 公开可读。部署版本、验证时间和源码提交见 `site/hosting.json`。

## 内容怎样更新

云端把 39 个信源分成 7 组。所有者登录后打开页面时，如距离上次检查超过两小时，会重新检查，所有者也可以手动检查。线索保存在云端 R2。目前没有独立定时任务。精选的更新日期取首次收录时间，信源检查取实际检查记录，卡片另列原文日期。已有的精选和它的详情链接会保留。

本地采集和云端检查各自运行。经本地整理的内容通过构建发布，云端已整理的增量通过 MCP 写入。读者收藏存储在当前浏览器。分享的详情页遵循站点访问权限。

## 构建和发布

1. 先用 Sites 源码助手打开 `site/hosting.json` 登记的现有项目，签出到主仓库同级的 `published-site`。保留此项目的框架依赖、云存储和 MCP 绑定。
2. 复核线索的正文和日期，用已有整理流程生成 `site/collected-content.json`。在 `site/reading-guide.json` 保存逐篇推荐理由、来源角色、事件、阅读路线和关联案例。
3. 在主仓库依次运行 `node scripts/build-preview.mjs` 和 `node scripts/build-site.mjs`。第二步将阅读界面、审核后的内容及 `site/cloud` 的云端功能写入托管源码工作区。
4. 在托管工作区执行 Sites 框架构建，使用源码助手推送与打包同一提交，再部署到原项目。通过原网址检查首页、文章深链、内容接口、最新线索和匿名权限。
5. 将实际部署编号、源码提交和验证结果写入 `site/hosting.json`，与主仓库的内容和代码一起同步 GitHub。采集原文、凭据和本地队列不入库。

## 公开访问

2026-11-05 已设置公开并通过未登录首页与详情页验证。页面保留 noindex、nofollow，robots.txt 允许读取页面上的不收录标记。公开链接可以转发，无法保证所有搜索引擎均不收录。

访客可以阅读和在本机收藏。检查信源和 MCP 调用仅允许所有者，服务端核对 Sites 验证身份与运行时 SITE_OWNER_EMAIL。此配置保存在 Sites 环境变量中。所有者可通过页面底部管理登录进入；没有启用无人值守定时采集。此后按公开站点的保存版本、部署流程发布。
