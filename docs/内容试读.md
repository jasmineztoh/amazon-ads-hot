# 内容试读

2026-10-29。进入instruction.md第4—5步：把已取得的真实内容、用户收录判断、试行推荐顺序和阅读页面接在一起。它是本地内容预览，不是已自动运行或对外发布的网站。

## 打开

在仓库根目录运行：

```powershell
node scripts/preview-content.mjs
```

浏览器打开 http://127.0.0.1:4173 。仅本机访问。端口被占用时可以另设`PREVIEW_PORT`；关闭启动窗口或按Ctrl+C结束。无需Docker、数据库或模型密钥。

## 这版能看什么

- 48篇用户已允许收录的真实内容，显示原文日期、中文摘要、要点、材料说明和原文链接。
- 六个已确认入口，文章可以同时出现在多个栏目。
- 搜索标题、摘要、要点和来源；按推荐顺序或原文时间排列；每次多看12条。
- 037/038同一事件合为一条，保留两个来源；搜索Skai仍能找到解读文章。总计48篇、47条。
- 推荐应用[收录标准v2](收录标准.md)。具体栏目与内容特征由Agent整理，用户没有填写的逐篇排序没有被补成用户标签。

页面只展示摘要和自行整理的要点，未公开原文全文。不编热度分，不把旧教程改成新消息，不把厂商效果改成本站验证。

## 文件与更新

正式用户标签在`docs/精选校准/标记.json`，收录材料在`docs/收录池.json`，Agent试读特征在`industry/preview-annotations.json`，排序和归并逻辑在`industry/curation.ts`。

更新材料或排序逻辑后，运行`node scripts/build-preview.mjs`，再刷新浏览器。它生成`site/preview/content.json`和浏览器使用的`curation.js`，不手改生成文件。48篇正文保存在被Git忽略的本地研究目录，构建与试读不依赖全文文件；收录池和页面材料已纳入版本保存。

`scripts/import-review.mjs`用于记录本轮48篇用户标记，逐条保留原36篇证据，核对本地正文哈希后补12篇；这是校准导入工具，依赖本机研究材料，不是网页启动的前提。旧标记有变更会停下，避免无历史覆盖。

这版没有新增应用数据库或公开API；因此没有绕过框架发布层把原文发布出去。正式接入主站时必须通过已有发布层读取，不把预览快照当长期的第二套生产后端。

- 48份本地正文快照哈希与原记录一致；5条用户原话、空白理由和收录许可分别保存。
- 内容构建成功；5项规则测试通过，覆盖降级不删除、优先顺序、品类错开、归并后搜索和48篇保留。运行`node --test-isolation=none --test industry/curation.test.ts`；Windows受限环境下采用不创建测试子进程的方式。
- 行业代码单独类型检查及全项目`npm run typecheck`通过；原前端生产构建通过。首次受限环境无法启动子进程，使用授权的本机运行通道完成。
- 本地首页与内容数据均HTTP 200，私有路径返回404。内置浏览器实际检查栏目、Skai搜索、要点展开、原文时间排序、加载更多、无结果提示，以及纯技术文章仍可找到。390px手机窗口无横向溢出，控制台未见错误。
